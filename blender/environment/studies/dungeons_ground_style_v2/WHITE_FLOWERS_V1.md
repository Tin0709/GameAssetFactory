# White flowers, one-block patch V1

Original editable study, **awaiting user art review**. Added through Blender MCP to the existing connected `dungeons_ground_style_v2.blend` window and saved at that exact path. The current window reflects the saved additions immediately. Background processes only reopen the saved file for validation and diagnostic renders; they never save or reload the live window.

Select `ENV_WhiteFlowerPatch_1m_V1` in `FLOWERS_White_1Block_V1`. A reserved 1 × 1 m planting square holds five unevenly spaced flowers: four blunt white rectangular petals, a flat yellow square centre, three thin stem quads and two blunt leaf planes per flower. All faces have zero thickness; no Solidify, cuboids or alpha cards. The mesh has 200 authored vertices, 50 quads and 100 triangles, with one matte opaque double-sided material. Source colours are original sRGB choices, stored as linear vertex albedo using `color_srgb`: white `#f3f4e9` / `#e7eee4`, yellow `#e8bf42`, stem `#4c7c3b`, leaf `#628947`. The user crop guided silhouette and distribution, without copied texture pixels or geometry.

Local Blender bounds are X −0.40547…0.38547, Y −0.39599…0.34870, Z 0…0.43420 m. The origin is the bottom centre of the reserved planting square. Flower-head centre heights are 0.300, 0.360, 0.400, 0.315 and 0.370 m. Source display location `(15, 3.2, 1)` is a review offset, not the runtime transform.

`game_mobile_3d/assets/environment/meadow_flowers_v1/white_flower_patch_1m.glb` exports only the selected flower mesh at identity transform. Blender Z-up converts to Godot Y-up once. It contains one mesh and one surface, with no camera, light, rig, animation, texture, morph target or collision. Keep the runtime vertex-color material/import handling supplied by the game integration. Colour is linear `COLOR_0`, not a bend mask.

The first UV map is motion metadata: source `UV0.x` is normalized stem attachment height; all flower heads/petals have exactly 1 and roots exactly 0. Each leaf stores one attachment height on all four corners so the plane stays rigid. Source `UV0.y` is flower-head centre height in metres. Standard glTF V flipping means the imported runtime height is **`1.0 - UV.y`**. The second UV map stores each flower root Blender `(X+.5, Y+.5)`; after glTF V flip and axis conversion, Godot local root XZ is **`UV2 - vec2(.5)`**. Do not lightmap-unwrap either metadata channel. Mesh FACE INT attributes `flower_index` and `flower_part` keep the five editable sets easy to select (parts: stem 0, petal 1, centre 2, leaf 3).

`REVIEW_Flowers_And_Original_Grass_V4` adds the original `ENV_Grass_Square_Leaves_V4` object from the [v4 source](../grass_block_reference_v4/README.md) as `REVIEW_Original_Grass_V4`. Its mesh, packed material/atlas and quiet Blender wind study are retained. `REVIEW_Meadow_Grass_V4_065` shares that exact mesh and changes only display Z scale to 0.65 (Godot Y scale). Each example stands on a copy sharing the existing current V3 grass-block mesh/material. All grass/plinth/camera/label additions are display-only; no new grass design was generated. The optional `CAM_Flowers_Grass_V1_Diagnostic` does not replace the existing scene camera.

`add_white_flowers_v1.py` is the additive live-session builder, and rejects duplicate generation. `validate_white_flowers_v1.py` independently opens the saved study and parses binary GLB accessors. It checks planar nondegenerate geometry, part counts, unit normals, footprint, opaque double-sided material, motion UVs, source-corner-to-GLB geometry/UV/linear colour agreement and preservation. It was first observed failing for a missing flower asset. The pre-edit byte backup and preservation baselines are under ignored `.validation/flower_patch_v1`; the stable audit excludes ephemeral Blender session IDs/cache state and compares all original data, including transforms, parenting, mesh UV/colour, material nodes and image pixels. Packed images are explicitly loaded before hashing. The independent background validation report is `.validation/flower_patch_v1/validation_source_and_glb.json`.

Diagnostic images show Blender source geometry, not runtime animation or phone performance. Godot visual review and gameplay wind are owned by the game integration. Art direction remains in [the existing graphics guide](../../../../docs/graphics/ART_DIRECTION.md).
